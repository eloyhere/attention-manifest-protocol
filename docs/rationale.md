# 设计决策记录（ADR）

**状态**：v0.1-draft · 2026-10

这份文档记录 AMP 为什么长成现在这样，尤其是**哪些看起来合理的设计被否决了**。每条决策按「背景 → 决定 → 理由 → 代价 → 证据」书写。编号稳定。

---

## ADR-001 目标的改写：从「认识宇宙」到「可检查的认知」

**背景.** 原始目标是「让 Agent 以科学的方式认识宇宙、认识概念、自己、别人」。这个目标有感染力，但它不是一个可验收的目标：没有任何观察能证伪「这个 Agent 认识了宇宙」。以此为目标，规范会退化成宣言，指标会退化成叙事。

**决定.** AMP 的验收标准改为四条可检查的性质：

1. **可声明**：Agent 当前的认知状态（知道什么、在注意什么、还缺什么）是显式对象；
2. **可计价**：每一次注意与推理都有预算与回执；
3. **可反驳**：每个假设都带反证条件，每个主张都带依据或明确标为猜测；
4. **可审计**：第三方能从日志重建「它当时为什么这么判断」。

「科学」在协议中不作为流程表演，而作为**一组义务**：可证伪、来源可追、修订留痕、承认未知。

**理由.** 协议只能约束「可观察的声明与行为」，不能约束「理解」。把无法验证的雄心写进规范，最终会导致两种失败：实现者用提示词假装满足，评估者用叙事代替证据。

**代价.** 放弃宏大叙事，对外表达不如原目标有感染力。缓解方式：把「认识宇宙」保留为**北极星**，把四条性质作为**可交付物**。

**证据.** 见 ADR-005（自述不可信）、ADR-004（认知投入分级）、§2 理论根基。

## ADR-002 两个账本，取代五个并列模块

**背景.** 最初的模型按本体论分成五个「世界」：世界、问题、计划、自我、他者，各自一套对象。问题在于：这是**知识的分类**，不是**机制的分类**。按此实现，每个模块都要造一套存储、一套更新规则，最后得到五个互不相通的小数据库，而注意力的分配逻辑无处安放。

**决定.** 核心收敛为**两个账本 + 一个控制器**：

| 账本 | 记录 | 回答 |
| --- | --- | --- |
| **Warrant Ledger**（凭据账本） | 主张、证据、依据、假设、未知、概念、计划（作为「我凭什么相信这个计划能成」的凭据） | 我凭什么相信？ |
| **Attention Ledger**（注意力账本） | 注意帧、预算、回执、打断 | 我的认知花在哪？ |

`Controller` 在两者之间做交易：**用注意力换取凭据**。五个世界降级为 `target.kind` 的枚举，而不是五个并列子系统。

**理由.** 机制比分类更接近可执行的东西。任何认知活动都可以还原为「我获得了什么凭据」+「我付出了什么注意力」；反过来，本体论分类无法告诉你下一步该做什么。

**代价.** 对象数量变少，但每个对象的语义变重；需要在文档里解释「概念、计划、他者模型为什么都是一种凭据」。

**证据.** Nelson & Narens 的元层/对象层区分（监控流 + 控制流）天然对应两个账本；SOAR/ACT-R 的教训是**少数机制 + 大量内容**，而不是大量机制。

## ADR-003 显著性：规定契约，不规定公式

**背景.** 初稿给出 `salience = VOI × goalFit × uncertainty × novelty / (cost + risk) × trustCap`。这个公式看似严谨，实则不可证伪：六个因子的取值范围、相乘的合理性、参数如何标定，全都没有依据。更糟的是，它会让不同实现之间无法比较。

**决定.** 规范性内容改为**评分契约**：

1. **输入字段**：每个候选对象必须可计算 `voi`、`cost`、`risk`、`trust`、`recency`、`goalFit`；
2. **单调性约束**（可测试）：`voi ↑ ⇒ salience 不降`；`cost ↑ ⇒ salience 不升`；`risk ↑ ⇒ salience 不升`；`trust` 只提供**上限**，不提供加成；
3. **校准要求**：实现必须记录 `voi_predicted` 与 `voi_realized`，并周期性报告二者的一致性；
4. **参考实现**：公式作为**默认实现**单独发布，允许替换，但必须满足 1–3。

**理由.** 可测试的约束比不可测试的公式更有价值。单调性是弱假设，几乎任何合理实现都满足；一旦实现违反单调性，就是 bug。校准要求把「显著性」从玄学变成可被数据修正的估计。

**代价.** 需要额外的埋点（预测值与实际值），短期增加工程量。

**证据.** 决策论中的 VOI 需要信念分布；LLM 运行时通常没有可靠分布，只能给出序数估计。序数估计足以支撑**排序与单调性**，不足以支撑**乘法公式的绝对数值**。

## ADR-004 认知投入分级 T0–T4

**背景.** 若要求每个判断都走「观察 → 假设 → 实验 → 结论」，Agent 会把绝大部分预算花在仪式上。真实科学活动的大多数判断是廉价的：引用已知机制、套用先验、类比、查表；只有少数关键分歧才值得做实验。

**决定.** 每个 `Claim` 必须声明**认知投入等级**：

| 等级 | 名称 | 凭据形态 | 晋级工件 | 允许的行动 |
| --- | --- | --- | --- | --- |
| **T0** | 假定（Assumed） | 无外部证据，仅有先验或惯例 | 无（必须标注） | 仅可逆、低风险行动 |
| **T1** | 有据（Sourced） | 来源**蕴含**该主张 | 来源 URI + 定位 + digest | 一般行动；不可逆需 T2 |
| **T2** | 验证（Observed） | 自己记录的测量，可重放 | `run_id` + 查询/配置 + 结果摘要 | 大多数行动 |
| **T3** | 检验（Tested） | 预注册的比较，指明识别策略 | 预注册哈希 + `assignment_mechanism` + `adjustment_set` | 不可逆、高风险行动；因果断言 |
| **T4** | 复现（Replicated） | 独立重跑（不同种子/数据/环境） | 独立 `run_id` + 差异说明 | 对外声明；跨任务复用 |

规则：**等级由声明给出，由证据校验**；宿主按行动的可逆性与风险设定最低等级。T0 不是耻辱，**未标注的 T0 才是**。

**理由.** 这把「科学方法」从流程改为**预算化的升级路径**：默认廉价，遇到分歧才付费。它同时解决了注意力经济与认识论两个问题——升级本身就是一次注意力分配决策。

**代价.** 需要定义「可逆性/风险」的分类，并与权限系统打通。

**证据.** 因果阶梯（Pearl 2009）区分观察与干预，T2/T3 正对应此界；可用性偏差与先验的价值（Tversky & Kahneman 1974）说明 T0 是常态而非缺陷。「T1 要求蕴含」来自 FActScore 一类原子事实核验：提到关键词不等于支持结论。

## ADR-005 只信任结构，不信任叙述

**背景.** 初稿让模型在 `Manifest` 里声明自己的校准程度、能力边界与注意力状态。但 LLM 的自我报告系统性不可靠：置信度普遍偏高，链式推理的解释常常与真实计算过程不符，社会压力下还会迎合。

**决定.** 三类信息的处理方式分离：

| 信息 | 对待方式 |
| --- | --- |
| **结构性事实**（调用次数、耗时、digest、结果大小、工具返回） | 可信，直接入账 |
| **模型的自由文本自述**（置信度、理由、计划说明） | 一律记为 `conjecture`，直到被结构或证据佐证 |
| **校准指标**（ECE、命中率、VOI 偏差） | **只由回执计算**，模型不得直接填写 |

`Manifest.self.calibration` 是**测量结果的展示位**，不是模型的输入框。

**理由.** 协议无法让模型变得诚实，但可以让不诚实**可被发现**。把自述与实测并列存放，是唯一可行的审计方式。

**代价.** 需要额外的行为埋点；某些「模型自我反思」的价值被削弱（反思仍需发生，但其输出不被当作事实）。

**证据.** 见 `docs/research/` 中校准与内省相关条目；ADR-001 的可审计要求。

## ADR-006 检索失败是一等结果

**背景.** 初稿假定 `find_tools(query)` 返回 top-k 即命中。证据显示这个假定很危险：在 43,215 个工具的 ToolRet 上，最好的检索器 R@10 也只有约 42–45%；在 3,251 个工具的注册表上，固定 top-5 只覆盖 64.7% 的任务，且当正确答案排名 6–20 时**完全召回不到**。另一项研究发现，用约束解码逼模型只输出工具名，会显著损害「不该调用」的判断（最差单元格 −29.5 个百分点）。

**决定.** 检索必须内建三条失败路径，且**弃权（abstain）是一等合法输出**：

1. `abstain`：低于校准阈值时返回空，并附 3 条建议与 `blocked_by` 原因；
2. `widen`：空结果触发一次上下文改写后的重检索；
3. `escalate`：被权限或状态阻断时，返回可升级的路径（申请授权、切换数据源）。

禁止用语法约束强制模型输出候选工具名。

**理由.** 一个把「没找到」当作异常的系统，会把所有失败都变成误调用；而误调用的代价远高于多一次检索。

**代价.** 需要校准阈值 τ，并设计空结果下的模型话术。

**证据.** ToolRet（arXiv 2503.01763）；shortlist 覆盖研究（arXiv 2605.24660）；约束解码与弃权（arXiv 2608.13959）。

## ADR-007 计划是部分的，且带承诺窗口

**背景.** 初稿要求 `Plan` 声明 `abandon_if`，但默认计划应尽量完整。这与 LLM 的实际能力不符：长程规划的错误率随步数上升，回溯能力弱，且完整的计划在第一步就可能失效。

**决定.**

1. **部分计划**：默认只展开到「下一个决策点」，即承诺窗口（commitment window）；
2. **承诺窗口由不确定性决定**：不确定性越高、可逆性越低，窗口越短；
3. **`abandon_if` 必填**，且必须包含至少一个**可观测**的触发条件；
4. **计划与过程分离**：`Process` 是「世界如何运作」的因果模型，`Plan` 是「我打算怎么做」的行动序列；前者可以独立于后者存在，后者必须引用前者（或显式声明缺乏过程理解）。

**理由.** Bratman 的计划理论指出，计划的功能是**约束未来的审议**，而不是预测未来；约束太紧会僵化，太松则失去协调价值。承诺窗口正是这个约束的粒度。

**代价.** 需要在执行中频繁重新规划，增加开销；对规划器的要求从「一次性正确」变成「持续可用」。

**证据.** 见 `docs/research/` 中规划基准与分解相关条目；Bratman 1987。

## ADR-008 分层：Core 不依赖 Profile

**背景.** 初稿把多智能体协商、实验、沙箱执行都写进核心，导致任何一个实现都要背全套复杂度。FIPA ACL 的失败提供了一个直接教训：语义过度规定、实现门槛过高，最终无人采用。

**决定.**

- **AMP Core**：Manifest、Frame、Receipt、Warrant、Attention 控制器、Plan。单 Agent 可独立实现。
- **Profiles**（可选，独立演进）：
  - `Exec`：工具/MCP/沙箱/句柄；
  - `Social`：他者模型、共同基础、注意力协商；
  - `Inquiry`：实验、T3/T4 检验、证据包；
  - `Federation`：跨 Agent 的清单交换与审计。

核心的一致性测试不依赖任何 Profile。

**理由.** 采用率取决于最小实现的门槛；功能深度可以后加，语义债不能。

**代价.** 一些跨层能力（如「向人类请求注意」）被推到 Profile，核心只保留接口。

**证据.** FIPA ACL 的采用失败；MCP 自身「核心 + extensions」的分层经验。

## ADR-009 预算在调度器强制，沙箱内不计费

**背景.** 初稿把预算检查放在执行器内部。真实事故说明了问题：CVE-2026-114386 中，Pydantic AI Harness 的 `UsageLimits.tool_calls_limit` 没有覆盖 `run_code` 内发出的嵌套工具调用，导致提示注入可以绕过配额。

**决定.**

1. 所有工具调用（含嵌套、并发、循环内）必须经过**同一个调度器计数器**；
2. 沙箱只负责执行，不负责计量；沙箱内的 `call_tool` 必须回到调度器；
3. 超限返回 `budget_exceeded` 并指明是哪一个维度，**不得静默截断**；
4. 每个 `run` 的用量写入回执，作为下一轮分配的依据。

**理由.** 计费点必须与授权点重合，否则一定被绕过。这是安全属性，不是性能优化。

**代价.** 沙箱调用有额外往返（参考：本地 1–2ms vs 代理 200–500ms），需要批量与缓存。

**证据.** CVE-2026-114386；Cloudflare Dynamic Workers 每次执行新建 isolate；FastMCP 对 `execute` 内工具调用设 50 次上限。

## ADR-010 清单摘要固定，漂移即安全事件

**背景.** 2026 年 9 月的一项普查（arXiv:2609.14119）发现：21,643 个服务器、72,606 个版本中，**51.1%** 的多版本服务器修改过自述元数据，其中 **40.6%** 是静默修改，**4.2%** 在保持注册身份的情况下把远程端点指向了别处。Deadbugz 攻击更进一步：前三次调用完全良性，之后改写工具描述以搜寻密钥。

**决定.**

1. 批准时固定 `H = SHA-256(JCS(compact_manifest))` 与每工具扩展 schema 的 `h_i`；
2. 在连接时、`ttlMs` 过期时、收到 `list_changed` 时**重新拉取并比对**；
3. 在每次 `tools/call` 时，用**实际用于参数校验的那份 schema** 重新计算 `h_i`（消除检查/使用之间的时间窗）；
4. 任何不一致：fail closed、标记为安全事件、要求重新批准；
5. 签名覆盖 `{resource, issuer, key_id, version, digest, iat, exp, nonce}`，`resource` 必须等于实际联系的端点。

**理由.** 「批准一次，永久信任」是这类攻击的结构性前提。摘要固定把信任对象从「名字」换成「字节」。

**代价.** 每次连接多一次拉取与哈希；清单变更需要重新审批，影响可用性。

**证据.** arXiv:2609.14119；Deadbugz（Pillar Security 2026-08）；CVE-2025-54136（MCPoison）；RFC 9728 的 `signed_metadata` 先例；SEP-1766（未批准）说明这是空白。

## ADR-011 签名证明密钥，不证明真实

**背景.** 初稿把「签名清单」当作信任基础，容易让人误以为签了名就安全。

**决定.** 明确三层区分：

| 层 | 证明什么 | 不能证明什么 |
| --- | --- | --- |
| 签名 | 某密钥签发了这些字节 | 服务器是它声称的那个、工具是安全的 |
| 来源 | 注册表/DNS/组织背书的身份 | 运行时行为未变 |
| 行为 | 回执与历史一致 | 未来不会作恶 |

**理由.** 在 2025–2026 的六个公开事故中，只有工具投毒与 Deadbugz 属于元数据完整性问题；GitHub、Asana、Supabase、Postmark 分别是权限过大、租户校验缺失、凭据过强与供应链问题——**签名清单一个都解决不了**。把信任层宣传成万能解药，会在第一次权限类事故中失去可信度。

**代价.** 对外表述更保守；需要与其他控制（最小权限、出站白名单、人工确认）配套。

**证据.** Invariant Labs 2025-04 / 2025-05；Asana 2025-06；Supabase 2025-07；Postmark 2025-09；Pillar 2026-08。

## ADR-012 与 MCP 的关系：扩展，不分叉

**背景.** 重造协议的诱惑很大，但 MCP 已有 36,134 条注册条目与全部主流客户端；而下一代工具协议真正缺的东西（清单、句柄、预算）恰好是**剖面**而非传输层。

**决定.**

1. 南向复用 MCP 2026-07-28：`server/discover`、`ttlMs`、`cacheScope`、`extensions`；
2. AMP 对象通过 `io.amp/*` 扩展与 `_meta` 传递；
3. 句柄是**普通字符串参数**，不新增线上类型（遵循 SEP-2567 Future Work 的方向）；
4. 不假设工具顺序稳定：MCP 只要求 SHOULD，AMP 自带顺序与摘要；
5. 渐进披露的规范依据引用 SEP-2640 Skills 的「MUST NOT retrieve files ahead of need」。

**理由.** 接入成本决定采用率；协议层的空白已经被官方文档明确留出（SEP-2127 把 primitive 定义留给后续 SEP）。

**代价.** 受 MCP 演进节奏约束；部分能力只能以客户端约定存在。

**证据.** MCP 2026-07-28 规范；SEP-2127；SEP-2567 Future Work；SEP-2640。
