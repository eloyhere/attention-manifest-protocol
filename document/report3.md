# 研究依据、证据质量与评测设计审计报告

审计日期：2026-11-06。本文完整阅读了 [refract.md](<R:/project/attention-manifest-protocol/refract.md>)（v1.8，2218 行）与 [MCP-Token税与下一代工具协议.html](<R:/project/attention-manifest-protocol/MCP-Token税与下一代工具协议.html>)（1763 行），并核验下列论文及部分一手工程材料。未读取其它 report 文件，未修改架构正文。论文结论属于外部资料；本文未执行论文代码、未复现基准，也未测量本项目实现。检索截至审计日，不保证穷尽所有最新论文；已纳入 2026-10-30 的多工具检索研究及 2026-10-25 修订的证据校准研究。

## 1. 审计结论

架构的研究方向成立：按需加载工具、限制结果进入上下文、引入外部验证、记录操作与版本、对多 Agent 协作计入成本，都有相关实证支持。但现有证据支持的是若干局部机制，尚不支持“L0–L8、六级生命周期、六种视图、八种注意力操作、Profession、证据贝叶斯融合组合后会整体降低错误率与总成本”的系统性结论。设计完整性不能代替增量效果证明。

优先修订五项证据边界：

1. **把“注意力”定义成运行时的信息选择与上下文调度。** 当前 `focus/blur` 通过排序、摘要、保留策略实施，并不直接控制模型内部 attention 权重。不能用 Transformer 注意力公式证明该调度器有效。
2. **把 Token、费用、准确率和时延分开验证。** 少进入模型的 token 可能降低费用，也可能因漏召回、重复检索、缓存失效和重试反而增加总成本。不能把 token 降幅当作准确率或时延收益。
3. **把 Receipt、Evidence、真值分开。** 签名和哈希证明来源与内容完整性；操作成功、输出符合 schema、测试通过，分别只证明相应断言，不自动证明用户目标正确达成。
4. **工具检索必须测所需工具集的完整性。** 单工具选择准确率、Recall@k、语义相似分都不足以判断多工具任务能否完成；前置登录、ID 查询、依赖工具尤其容易漏掉。
5. **独立性与置信度需要校准实验。** “不同 Agent”或“不同工具”不是统计独立性条件；固定可靠性数值、佐证乘数、信任乘法与贝叶斯平滑，目前均是待验证的设计选择。

建议先证明一个受限命题：在明确的工具数量、任务类别和模型配置下，采用按需发现、结果句柄、外部验证和可追踪回执，相对简单强基线，在端到端成功率不劣于约定边界时，降低全任务费用或尾部时延。之后再逐个引入层级、脑图、Profession 和学习沉淀。

## 2. 证据等级与核验口径

本文使用四种证据类型，类型不直接等于可信度排名：

| 类型 | 可以支持什么 | 不能推出什么 |
|---|---|---|
| 论文实测 | 在指定模型、数据、实现与评估规则下观察到的差异 | 全场景、全模型、因果机制已确定 |
| 模拟/计数/数学推导 | 指定假设下的 token、复杂度或资源量 | 真实 Agent 的成功率、安全或时延 |
| 厂商内部评测/工程示例 | 功能可实现、某种部署下有收益 | 独立复现、统一基准、跨厂商可迁移效果 |
| 架构假设/规范性约束 | 期望的不变量与实现契约 | 已取得性能收益、实现已经遵守契约 |

arXiv 发布意味着资料可定位，不等于同行评审。以下标注 ICLR/TACL 的论文可确认相应发表信息；2026 年预印本若页面未给出接受记录，本文按预印本处理。论文版本、数据快照、代码提交与模型版本应进入后续本地实验记录，避免引用更新后数值变化。

## 3. 与架构直接相关的研究证据

### 3.1 工具调度：已有 token 证据，端到端收益有条件

**[P1] Tool Attention Is All You Need（2026-04-23，v1）**  
论文 URL：https://arxiv.org/abs/2604.21816  
正文 URL：https://arxiv.org/html/2604.21816v1

论文把句向量 ISO 分数、状态/权限前置门控和两阶段 schema 加载组合为中间件。在 120 工具、六服务器的校准模拟中，工具 token 从 47.3K 降至 2.4K，降幅 95%；“有效上下文利用率”从 24% 到 91% 是 token 比率。作者明确声明任务成功率、费用、时延、推理质量与对抗效果属于投影，未在真实 LLM Agent 上测量。

这支持 L2/L3/L4 的可实现性与定义 token 的潜在降幅，不支持本架构减少错误率的实测声明，也不能证明脑图、证据融合、Profession 或八操作的增量价值。论文用“注意力”作机制类比；ISO 不是模型的真实注意力分布，语义分数低也不意味着某工具安全可删。论文关于约 70% 上下文利用率断崖的依据包含工程报告，不能升级为统一阈值。

**[P2] GatewayBench（2026-10-16，v1）**  
论文 URL：https://arxiv.org/abs/2610.23449  
正文 URL：https://arxiv.org/html/2610.23449

该研究比较七个网关、三种模型与 harness 组合；任务集共 524 条、六个领域，噪声池包含来自 251 个服务器的 11,118 个真实工具定义，每任务最多注入 1500 个不相关工具。任务和攻击结果通过环境终态规则评估，强于仅判断调用文本。

关键结论有明确条件：

- 小工具集下，全量暴露减少发现轮次，可能更快、更便宜；工具规模增大后，全量暴露的 token 和处理时延增长，分层发现更稳定。
- 分层收益与模型能力相关，较弱模型可能因发现负担损失良性任务成功率；强模型能缩小能力差距。
- HTML 引用的间接攻击成功率 **60.5% 与 19.6%**，对应**无噪声、OpenAI SDK + GPT-5.1、对各架构类型内网关取均值**，不是所有场景的攻击率。其它配置也呈安全差异，但数值不同；差异主要来自工具描述注入。

证据局限：主实验因成本只运行一次；网关采用默认配置，产品差异不完全等同于单一架构因素。噪声工具定义真实，但实现为报错的 mock，并由 LLM 过滤为领域不相关，未充分覆盖最难区分的同领域近邻工具。74 条 MCP-Universe 任务还经过人工去除太简单和太困难任务，存在选择边界。可据此设计本地实验，不能直接宣称本架构会复现其收益。

**[P3] Completeness and Cost of Retrieval Structures for Multi-Tool Requests in LLM Agents（2026-10-30，v1）**  
论文 URL：https://arxiv.org/abs/2610.41905  
正文 URL：https://arxiv.org/html/2610.41905v1

这是对当前设计最关键的新补充。研究比较平面检索、查询分解、LLM 层级导航、先服务器后工具、依赖图和训练式集合检索，使用 345 条 AppWorld 查询及 103 条 MCP-Bench 任务。

- 在 ToolRet 的子数据集内检索设置中，单目标 completeness@10 为 0.58–0.67，四个及以上目标只有 0.08–0.17；单目标上的方法排序可在多目标任务上反转。
- 所测零样本、每查询至多一次 LLM 调用的方法，在 AppWorld 上 completeness@16 均不超过 10%；这只描述文中具体实现和编码器，不能说所有轻量检索都受此上限约束。
- 经域内训练的 COLT 在两个主测试床达到 0.328/0.583；AnyTool 层级导航为 0.301/0.398，但中位数需要 31/38 次 LLM 调用及约五分钟。更高召回不是免费的。
- 60 条下游试验中，COLT 返回完整工具集的任务成功 21/21，工具集不完整的任务成功 2/39；给同一批不完整任务 gold 工具集后成功 26/39。完整与不完整分组本身是观察比较，但同任务 gold 干预进一步显示漏召回的影响。

证据局限：LLM 步骤统一用 DeepSeek-V3.2；通用检索主要使用 base 规模编码器；MCP-Bench 参考工具集来自生成计划，并不一定是唯一合法方案；部分方法有兼容性改动或简化。研究仍然直接要求本架构把 Skill/Tool 的前置依赖纳入检索目标，并提供扩大预算、继续发现、等价工具和明确弃权路径。`associate 深度≤2`、固定 top-N、只保留当前路径，都应当作为可调实验变量。

### 3.2 格式与结果：无损序列化也可能让模型失误

**[P4] Notation Matters（2026-06-17，v2）**  
论文 URL：https://arxiv.org/abs/2605.29676  
正文 URL：https://arxiv.org/html/2605.29676v2

研究在 BFCL、MCPToolBenchPP、MCP-Universe、StableToolBench 和五种开放权重模型配置上比较 JSON、TOON、TRON，并区分仅输入压缩与连工具调用输出也替换的实验。输入压缩下，每模型跨基准平均总 token：TOON 降 2%–18%，TRON 降 0%–27%；准确率变化高度依赖模型和任务。全链路替换可因解析失败触发额外推理，部分配置总 token 反增 8%–11%，并行调用生成还出现严重失败。

HTML 的“TOON ≤18%、约 -9pp”可作为论文摘要中的量级描述，但不能当作所有格式整形的统一代价。论文没有单独隔离 schema 压缩与结果压缩；部分外部 API 类别被排除；模型规模为 17B–32B 活跃参数，不能直接外推到闭源前沿模型。

**必须区分三类机制**：TOON/JSON 之间的确定性序列化可以无损；字段投影/截断可能丢信息；LLM 摘要会引入遗漏或改写。HTML 将“输出整形”整体称为不可逆压缩，以及把单篇格式试验的准确率损失推广到分页、句柄、聚合，均过宽。正确实验应分别测格式理解、生成解析、字段保真与任务成功。

### 3.3 长上下文、文件路由与跨轮记忆：支持做选择，不支持固定摘要配方

**[P5] Lost in the Middle（TACL 2023）**  
论文 URL：https://arxiv.org/abs/2307.03172

多文档问答与键值检索显示，关键信息位置会显著影响表现，许多受测模型在上下文首尾优于中间。它支持“上下文位置需要评估”，不能证明所有现代模型必须把 Goal 置顶，更不能给出 70% 的通用断崖。应在当前模型上随机交换目标、约束、工具描述和证据的位置来重测。

**[P6] Agent Retrieval Bench（2026-07-27，v1）**  
论文 URL：https://arxiv.org/abs/2607.24882

427 样本、25 仓库，包括 code2test、comment2context、trace2code、edit2ripple 及无 gold/错误仓库控制。相关性按“下一步需要什么文件”定义；没有一种检索家族全面领先，RepoMap 在 8K token 预算的上下文产出上最优，而嵌入方法分别在 MRR/Recall@20 领先。错误仓库控制上校准的弃权阈值未改善自然无 gold 样本表现，说明“低置信度返回空”也有分布迁移问题。

这支持 L0.5 文件大纲与 L3 路由的任务化评测，不支持脑图天然优于词法检索。当前只是文件级证据，不能当作 AST 写入安全或符号级路由优势证明。

**[P7] LongMemEval（ICLR 2025，v2）**  
论文 URL：https://arxiv.org/abs/2410.10813

500 个问题覆盖信息提取、多 Session 推理、时间推理、知识更新和弃权，并将记忆拆成索引、检索、读取三个阶段。研究指出持续交互中的记忆准确率明显下降，并提供分解 Session、事实增强索引和时间查询扩展的实验依据。

它支持 Session/Turn 记忆需要专项评价，但未证明“历史一两行摘要 + persist bool + 工具细节默认不保留”足够。尤其需要测授权撤销、新意图覆盖、旧事实更新和中断恢复，不能只测一般事实问答。

**[P8] CliffCompaction（2026-09-22，v1）**  
论文 URL：https://arxiv.org/abs/2609.26779

摘要报告在 Terminal-Bench 上最高降低约 50% 费用并保持或改善表现，方法只删除或截取原始内容、不改写，也不再次压缩先前压缩结果，以避免漂移累计。本文核验到摘要，未独立核验全部实验表，因此只作为近期替代路线和复现候选。

这使“每次结果都用另一个 LLM 摘要不可行”“历史摘要一定比保留原文好”都不宜写成普遍判断。应比较原文抽取、确定性字段投影、重写摘要、句柄回取；将压缩计算和后续补读一起计入全任务预算。

### 3.4 验证、融合与多 Agent：一致性不是真值

**[P9] Large Language Models Cannot Self-Correct Reasoning Yet（ICLR 2024）**  
论文 URL：https://arxiv.org/abs/2310.01798

研究发现，在受测推理任务中，仅靠内部能力、无外部反馈的自纠可能失败甚至降低准确率。这支持独立执行反馈与外部验证的必要性，不能扩大为“所有 2026 模型的自检都无效”。架构需要对照“自检、工具检查、独立判据、人工判断”，而非用此论文证明任意 L6 验证器足够。

**[P10] Calibration Is Not Verification: Answer-Level Conformal Guarantees for Mixture-of-Agents（2026-10-25，v2）**  
论文 URL：https://arxiv.org/abs/2609.25959

论文明确区分多 Agent 的语义支持与事实验证。在交换性及策略校准前冻结等假设下，答案层校准可控制保留无支持声明的边际风险，但无法修复共同错误。FactScore 上达到较高事实支持率的同时，只保留 1.7%–9.8% 的受支持声明，且 30%–75% 答案为空。本文核验摘要；这些数值只适用于其 Web 综合任务和校准设置。

直接启示：L7 不能只报告后验均值或“正确声明比例”，还必须报告覆盖率、弃权率、被丢弃的正确信息和支持证据是否真实。否则系统可用大量拒答轻易提高表面正确率。

**[P11] Towards a Science of Scaling Agent Systems（2026-04-08，v3）**  
论文 URL：https://arxiv.org/abs/2512.08296

260 个配置、六个 Agent 基准、五类架构、三个模型家族的受控实验指出，多 Agent 效果依赖任务可分解性、模型能力和协调方式；工具密集任务有额外开销，缺少集中验证的架构更容易传播错误。相对单 Agent 的变化从可分解金融推理的 +80.8% 到顺序规划的 -70.0%。这些是特定任务的相对变化，不能换成百分点，更不能作为本项目协作收益目标。

这支持将 Cooperation 作为按需策略并设置收敛与预算；没有证明五种拓扑必须全部实现，也没有证明 Task 是所有跨 Agent 协作的最优粒度。

**[P12] Voyager（2023，v2）**  
论文 URL：https://arxiv.org/abs/2305.16291

Minecraft 中的可执行技能库、环境反馈、迭代改进与技能复用展示了成功轨迹沉淀的可能性。它是领域实例，不能证明三次成功足以形成通用 Behavior，或证明 Profession/Behavior/Skill 的当前划分最优。应以未见任务、工具新版本和环境漂移下的迁移效果检验 L8。

### 3.5 安全基准：必须同时测正常效用与攻击后的行为

**[P13] AgentDojo（2024，v3）**  
论文 URL：https://arxiv.org/abs/2406.13352

提供 97 个现实任务、629 个安全测试案例及可扩展攻击/防御环境，研究工具返回的不可信内容如何劫持 Agent。受测模型即使无攻击也会失败，所以安全效果必须在正常任务能力基线上解释。该基准支持本架构的工具结果注入评测，但不能替代沙箱逃逸、跨租户授权、句柄隔离、签名供应链等系统安全测试。

**[P14] MCP-Universe（2025-08-20，v1）**  
论文 URL：https://arxiv.org/abs/2508.14704

六领域、11 个真实 MCP 服务器，提供格式、静态和动态执行评估；强调长任务与陌生工具的困难。其执行判据适合检验 Task/Goal 完成度，但实时服务会漂移，要同时保留冻结环境回归和受控在线巡检，不能把服务不可用一律归因于架构。

## 4. 两份材料中的声明应如何收紧

| 现有声明或关系 | 审计判断 | 建议可发布措辞与补证要求 |
|---|---|---|
| 减少 token = 保持注意力密度；降低错误率 = 注意力不错配 + 验证兜底 | 设计口号，无可检验的等式定义 | 改为“通过信息选择与验证尝试降低成本和错误”；分别定义相关信息覆盖、冗余率、最终成功率 |
| 全量 schema 注入是 MCP 必然要求 | 把协议、host 策略与模型 API 混合 | 标明这是常见客户端策略；MCP 工具发现并不意味着必须全部进入模型提示 |
| Transformer 注意力 O(L²) 导致长上下文一定更差 | 计算复杂度与认知效果混淆 | 标准全注意力训练/预填充具有二次项；KV 缓存下逐 token 解码等成本结构不同；质量用当前模型实测 |
| 上下文达到 70% 后质量非线性下降 | 工程经验和模拟引用，不是跨模型定律 | 作为待校准告警点，测长度×干扰×位置×任务曲线 |
| 工具检索 token -85%、准确率 +25pp | 可追溯厂商内部结果 | 保留模型、评测类型与未独立复现标签；不能当作本架构承诺 |
| 固定四个元工具，接口面积永不随后端增长 | 仅入口 schema 可恒定 | 检索结果、inspect、代码、帮助、权限与错误仍可能增长；测完整发现到执行过程 |
| 北向约 300 token、单工具清单约 35 token | 示例/估计 | 附 tokenizer、完整描述、schema、语言及计数脚本后才能作为测量值 |
| 签名清单、沙箱与出站白名单足以安全收敛 | 有效控制但不充分 | 还需对象级授权、租户绑定、凭据隔离、每次子调用授权、撤销、句柄隔离、实现版本绑定与审计脱敏 |
| 隐藏视图，“省 token 零幻觉” | “零幻觉”无依据 | 结构验证器只覆盖形式化属性；语义建模错误、摘要错误及遗漏仍会传播 |
| DAG 无环即可验证终止性/无竞态 | 只对有限静态调度局部成立 | 重规划、重试、异步等待、工具内部循环及资源锁仍需超时、次数上限和活性检查 |
| AST 重写防破坏语法/文件写入安全 | 只能覆盖可解析性的一部分 | 需测试语义、格式保真、宏/嵌入语言、编码、冲突与 TOCTOU；AST 合法不等于行为正确 |
| 成功工具调用产生 Evidence，Goal 只认操作历史 | 缺少判据适用性检查 | 每条证据绑定原子声明、环境、判据版本、覆盖边界与独立观察；允许事实类任务使用可核验文献 |
| 操作历史 r=0.9、搜索 r=0.6、规则 r=0.95 | 未校准的常数 | 作为启发式配置明确标注，按声明类型、来源与环境校准，不称客观概率 |
| 不同工具/不同 Agent 验证同一事实即独立 | 条件不足，可能同源 | 追踪底层数据、测试 oracle、模型、提示和共享上下文；未知相关时保守合并 |
| 三次独立成功即可抽象 Behavior | 适合作为候选发现门槛，非效果证明 | 保留为工程阈值；上线需有失败/边界样本和独立留出集，不能只看成功轨迹 |
| 五拓扑、六视图、六级意图是必要组成 | 未有最小性或最优性证据 | 作为可选模块，通过消融说明每个模块解决的具体失败类型 |

一手工程资料也需要保留：Anthropic Advanced Tool Use 的可访问来源为 https://www.anthropic.com/research/advanced-tool-use 。其明确报告 Opus 4 49%→74%、Opus 4.5 79.5%→88.1%，并说明是内部测试；72K 是全量工具定义量级，8.7K 是检索后总上下文量级，**两端口径并不完全相同**。同页的 PTC 43,588→27,297 为复杂研究任务平均 token，不能和单个 150K→2K 示例相乘得到整体节省。

已访问 MCP 2026-07-28 官方变更记录 https://modelcontextprotocol.io/specification/2026-07-28/changelog ，确认无状态化、移除协议 Session、引入 discover 等变更。这是规范证据，不是性能基准。协议 Session 的移除不否定应用层 Session；无状态也不自动使有副作用工具幂等，更不保证旧端点零改造兼容。本文未对 HTML 所有生态计数、安全个案、商业机构统计和项目星数逐一独立核验，它们不进入架构收益的定量依据。

## 5. Token、费用与时延的计量模型

### 5.1 先固定计量单位

至少分开 `用户 Turn`、`LLM request`、`tool call`、`sandbox run`、`Task` 和完整 `Session`。一个用户 Turn 往往含多次模型调用，直接拿“每轮定义 token”与用户 Turn 对齐会少算。回执应记录请求级计数，再向 Task/Turn/Session 聚合，不能将父子汇总回执重复求和。

每次模型请求记录：静态系统提示、工具入口/定义、检索结果/文档、当前目标与约束、历史消息、工具结果、摘要、证据/回执摘要、Agent 通信；同时记录输出 token、供应商计费的推理 token（若可见）、缓存读取/写入 token、模型与 tokenizer 版本。无法分段精确取得时，明确估计值及误差，不将本地 tokenizer 估计等同于实际账单。

全任务费用至少为：

`LLM 输入未缓存费用 + 缓存读写费用 + 输出/推理费用 + embedding/reranker/摘要模型费用 + 工具/API 费用 + 沙箱/存储/索引摊销`。

必须包含失败任务、重试、重新发现、人工介入与补读句柄。主要经济指标建议使用“总花费 / 正确完成任务数”，并并列报告每分配任务平均花费，避免只保留成功轨迹制造节省。

### 5.2 O(N²) 是特定重放策略的结果

若第 i 次结果大小为 r_i，并在后续每个模型请求完整保留，则累积结果输入量为：

`T_result = Σ(i=1..N) (N-i+1) × r_i`。

在每次相同大小 r、无裁剪且计算包含结果首次消费的定义下，等于 `rN(N+1)/2`；若不计最后一次消费，系数略有不同。固定定义 d 的累计量为 `dN`。缓存、滚动窗口、压缩和执行外置会改变费用与增长方式，因此“结果税总是二次、必须优先于定义”不能脱离实际工作负载。

HTML 的 Fig.02 有一个需纠正的计算口径：每次 2K、20 次完整累计为 420K 正确；若代码模式**每次仍向对话追加 0.2K 且全部重放**，累计应为 **42K**，不是 4K。4K 是 20×0.2K 的新增输出总量，或需要额外说明每步旧摘要不重放/被替换等策略。不能在两条曲线上比较不同计量口径。

定义 d=55K、每步 r=10K 时，第 11 步累计结果首次超过累计定义，这个条件推导成立；它不是所有数据型任务的经验分界。

### 5.3 缓存与时延要独立记录

缓存比例可用“读取缓存 token / 可缓存输入 token”与“请求缓存命中率”两个指标表达，不能将 cached_tokens 占全部输入的比例混称命中率。测试冷启动、暖缓存、跨租户、schema 更新、权限变化与目录顺序改变；动态目录缩短后仍可能因前缀变化增加费用。

时延拆成发现、检索、rerank、schema 展开、排队、模型首 token、模型生成、工具网络、沙箱启动/执行、验证、合并和回滚。报告端到端 p50/p95/p99、超时率、首次可用结果时间及正确完成吞吐。并行调用用关键路径计算端到端时延，不能把各调用耗时总和当作用户等待时间。减少 19 次模型往返仍可能新增代码调试、重试和冷启动，净收益必须实测。

## 6. 证据融合与安全的具体修正建议

### 6.1 声明级证据，避免“工具返回即真值”

建议将 Evidence 至少增加为：`claim_id`、原子断言、观察对象/环境版本、原始结果指针与哈希、采集者、判据与判据版本、有效时间、覆盖范围、来源派生链、失效条件。Receipt 保存操作事实；验证判据对断言做判断；Evidence 引用这两者及观察值。形式校验和业务验收应产生不同断言。

例如“测试命令退出 0”“目标测试全部执行且通过”“修改后满足用户需求”是三条断言。前一条不能自动向上证明后两条。空测试集、被跳过测试、错误目录、mock 与真实服务差异、判据本身出错，都能产生“成功操作”的假阳性。

用户确认适合确认意图与授权，不必然验证外部技术事实；学术事实可以由论文支撑，而“调用搜索工具成功”不应被提升为论文结论正确。`system_rule` 是政策或决策记录，将其赋 0.95 真值权重会把系统自己的判断洗成高可信证据。建议把“规范性权威”和“经验事实可靠性”设为不同维度。

### 6.2 独立性与贝叶斯模型

`independence_key` 可以去重，但无法证明独立。两条回执可能来自同一文件、同一错误 API、同一训练模型、同一测试 oracle；两个 Agent 还可能读到相同摘要。同源应按底层 provenance 图聚类；来源关系未知时标记 unknown，不默认独立。

可靠性×新鲜度×独立权重×佐证数只是评分公式。要称为后验概率，必须给出事件定义、先验、似然、相关结构及校准结果。Beta-Binomial 适合明确的二元成功试验，在可交换/相应独立同分布等假设下估计同类试验成功率，不能直接把不同事实、来源权重和同源转述当作等价 Bernoulli 样本。

若采用近似等相关模型，可做敏感性分析：`n_eff ≈ n / [1+(n-1)ρ]`，但不能把这个近似当作真实相关性的已知答案。报告 Brier score、可靠性图、ECE（说明分箱）、置信区间覆盖率、风险—覆盖曲线、漂移后校准退化。先验强度、遗忘因子、切换 w、滞后与阈值必须在开发集选择，测试集冻结。

仅从 mounted/成功执行样本更新，会有选择偏差。现有对 unmounted 候选抽样的方向正确，还需记录被选择概率、失败与弃权样本；影子实验必须隔离副作用。撤销深度达到上限时，要让未遍历后继进入待重验/保守不可用状态，不能留下可继续消费的旧结论。

### 6.3 安全控制与评测不能互相替代

Manifest 的 digest 若只覆盖描述，不能绑定真正运行的实现、依赖、端点、权限与配置。可信工具仍可能处理恶意用户内容；有签名的恶意工具仍然恶意。审批与执行必须绑定相同版本及参数范围，且每次执行重新校验当前授权。

代码模式应在每个 SDK 子调用处校验身份、对象与范围，不能只在 `run` 入口授权。句柄必须绑定租户、会话、资源分类与权限版本，支持过期、撤销和不可猜测标识；缓存键要包含授权相关维度。出站白名单也必须检查经允许的邮件、PR、工单等工具流出的数据，不能只限制沙箱直接联网。审计日志和 Receipt 需要脱敏，防止把密钥与敏感数据长期复制进证据库。

安全指标应包括正常成功率、攻击下用户任务成功率、攻击成功率、越权调用的尝试与实际执行率、外泄字节/敏感字段、误拦截、句柄串租户、审批参数替换、撤销生效时间、重放重复副作用。攻击必须分别覆盖工具描述、返回数据、检索索引、技能文件、跨 Agent 消息、摘要/记忆和实现供应链。不能只测试容易被检索器过滤掉的不相关恶意工具；也要测会被高分召回的任务相关恶意内容。

## 7. 可执行的评测设计

### 7.1 基线和数据分层

至少保留以下对照，所有配置共享模型、权限、工具版本、任务初态、预算和判据：

| 配置 | 用途 |
|---|---|
| B0 简单 ReAct + 全量工具 + 结构化结果 + 相同外部判据 | 测复杂架构相对简单系统的净增益 |
| B1 静态 toolsets/权限过滤 + 稳定前缀 + 缓存 | 排除收益仅来自常规工程优化 |
| B2 BM25/混合检索 + 延迟 schema + JSON | 作为强的按需工具基线 |
| B3 B2 + 确定性字段投影/分页/句柄 | 独立检验结果预算与外置 |
| B4 B3 + 代码编排 | 检验往返与中间数据外置 |
| A 待审架构的最小实现 | 与最接近强基线比较，不只比较最弱基线 |
| Oracle 相关工具/文件/依赖集合 | 诊断检索瓶颈与执行能力上限，不能作为部署配置 |

任务至少覆盖：单工具与 2/4/8+ 工具；前置依赖链与独立集合；10/50/200/1000+ 工具目录；同领域近名干扰与跨领域噪声；只读/写入/不可逆动作；短查询/数据聚合/代码修改/跨轮修订；自然无匹配与工具故障；英语/中文和组织内部术语。数量网格是实验建议，并非已有性能阈值。

真实私有任务、公开基准和合成压力任务分开报告。按仓库、工具家族、模板和时间切分训练/开发/测试，防止近重复任务、成功轨迹和文档泄漏到测试。集合 gold 允许等价替代方案和多条合法路径；人工双人标注并仲裁分歧，不能只拿某一计划作为唯一正确调用序列。

### 7.2 评测分三层，避免把完整系统当黑盒

1. **确定性契约层**：验证拒绝非法状态迁移、预算守恒、版本不匹配写入拒绝、租户隔离、回执不可篡改、撤销传播、中断重放幂等、重复提交和并发更新。使用属性/状态机测试与故障注入，判据独立于 LLM。
2. **模块层**：工具完整集召回、文件/符号定位、摘要原子事实保真、结果格式解析、置信度校准和新行为触发副作用。
3. **端到端层**：独立环境终态验证 Task/Goal，记录所有失败、弃权、人工介入、费用、时延与安全事件。规则判据自身也做人工抽查和突变检验，不能由同一个 Agent 自拟、自执行、自认证后宣称独立验证。

### 7.3 必须统一的指标

| 维度 | 主指标 | 防止误判的配套指标 |
|---|---|---|
| 成功 | 全部必要验收通过的端到端成功率；成功率差及置信区间 | 部分完成、不可恢复副作用、人工介入、失败归因；多次尝试成本 |
| 检索 | `completeness@k = mean[所需合法工具集 ⊆ 返回集]`，按所需集合大小分层 | Recall/Precision@k、前置依赖召回、等价路径、扩大检索次数、无匹配精确/召回 |
| 文件路由 | gold 文件/符号覆盖、预算内有效上下文量 | 误路由、跨文件影响遗漏、stale 命中、补读成本 |
| Token | 请求级及全任务累计输入/输出/推理 token，结果重放量 | 调度/摘要/通信/验证开销、冷暖缓存、父子去重聚合 |
| 费用 | 每分配任务费用；总费用/正确完成数 | 离线建库/训练/存储摊销与长尾失败费用 |
| 时延 | 正确完成的端到端 p50/p95/p99，及全样本超时率 | 首次可用结果、失败提前退出、队列/冷启动/重试/关键路径 |
| 置信度 | Brier、校准图、风险—覆盖曲线 | 空答案率、错误高置信率、漂移、相关性敏感性 |
| 安全 | ASR 与实际越权/外泄率 | 正常效用、攻击下效用、误拦截、危害严重度、尝试次数 |
| 可恢复性 | 恢复后终态与参考运行等价比例 | 重复副作用、预算漂移、证据/句柄失效延迟、取消滞后 |
| 学习 | 未见任务上的成功率/费用变化 | 触发准确率、负迁移、副作用、工具版本漂移、回滚效果 |

### 7.4 配对试验、样本量与统计处理

同一任务初态下按配置配对运行，随机交错顺序控制 API 波动；先用三次重复估计随机性，再按功效决定正式重复数。模型温度为 0 仍不等于无随机性。按任务/仓库簇做配对 bootstrap，二元配对差异可用 McNemar；同时报告绝对百分点、相对变化和置信区间。时延与费用分布常偏斜，不能只给均值。

HTML 提议人工标注 200 条请求适合作为 pilot，不能自动支撑细粒度结论：若成功率约 90%、n=200，在独立二项近似下 95% 区间半宽约 4.2 个百分点；分层后更宽。若要证明 1–2pp 的非劣性，需要依据配对不一致率和功效重算样本量。安全试验即使 300 次零事件，独立近似下 95% 单侧上界仍约 1%，不能发布“零风险”。

预注册主成功指标、非劣性边界、费用/时延目标、失败计入规则、停止条件及多重比较处理。测试集不得用于反复选择 top-k、可靠性权重、摘要预算或 Profession；论文数值与 HTML OKR 都只可作为候选目标，须由 P0 本地实测替代。

## 8. 最需要实验验证的模块关系

| 编号 | 待验证关系与假设 | 最小消融/干预 | 通过前不应声称什么 |
|---|---|---|---|
| E1 | L3 调度 → L4 上下文 → 最终成功 | 全量、静态过滤、检索、oracle；固定总预算，改变干扰与位置 | 注意力密度本身造成成功率提升 |
| E2 | 脑图/associate 跨边 → 更完整召回 | BM25/向量、树、同预算图；移除/打乱关联边；测深度1/2/更深 | 六种视图或深度≤2 已最优 |
| E3 | 状态门控 → 安全且不阻断可达任务 | 禁止调用与暂不满足前置分别处理；允许发现认证/依赖；注入状态变化 | “没登录的工具不召回”总是正确 |
| E4 | Budgeter + Handle → 全任务费用下降 | 相同内容做全量、分页、句柄、字段投影；覆盖补读/过期/重建 | 转句柄一定省 token 或不损准确率 |
| E5 | 代码编排 → 减少往返且安全可审计 | 与同并行度工具调用比较；纳入代码错误、冷启动与子调用回执 | 20 次工具调用必省19次推理或沙箱入口恒定即复杂度恒定 |
| E6 | L6 形式约束 → 更少业务错误 | schema/状态验证、独立终态判据、二者组合；注入合法但错误结果 | “确定性验证”覆盖语义正确性 |
| E7 | Receipt → Evidence → calibrated confidence | 插入签名有效但内容错误/判据错误回执；共享来源和重复 Agent；检验校准 | verified 回执就是可信事实 |
| E8 | 撤销/快照 → 长任务正确恢复 | 撤销中间证据、深度截断、服务变更、并发读写、崩溃后恢复 | 文件回滚可撤销远程发信/支付等所有副作用 |
| E9 | Turn 重置/persist → 少污染且不丢约束 | 全历史、摘要、原文抽取、结构记忆；不同重置时机；授权撤销与新 Intent | Turn 是最佳遗忘边界；一两行摘要足够 |
| E10 | Profession → 更好能力选择/验证 | 仅角色文本、权限约束、验证策略、完整画像；保持总预算 | 职业身份独立产生收益，或角色提示能替代权限 |
| E11 | L8 Behavior → 可迁移收益 | 未使用、固定内置、学习行为；轨迹去重；未见任务/新版本留出 | 三次成功足以泛化；成功样本不存在选择偏差 |
| E12 | Cooperation 拓扑/粒度 → 成本与成功优势 | 同总模型预算下单 Agent、独立并行、主从；Task/细粒度边界比较 | 多 Agent 或五拓扑普遍优于单 Agent |

E3 特别容易形成调度死锁：某目标工具当前未满足登录/资源前置，于是被彻底隐藏；Agent 又不知道需要先取得这些前置。权限禁止和可通过工作流满足的暂时不可执行应分离，后者可以暴露安全的“不可执行原因/所需依赖”，执行时再强制授权。E7/E8 是学习沉淀的前提：未证明判据可靠和撤销完整前，不应自动把成功轨迹升格为高可信技能。

## 9. 建议的研究落地顺序与声明模板

**第一阶段：测量和强基线。** 建立请求级 token/费用/时延/判据账本，完成 B0–B3；先测工具全集召回、结果补读与缓存。此时只发布本地观测，不给整体架构优越性结论。

**第二阶段：验证与故障。** 用环境终态、错误回执、撤销、中断、并发、租户和句柄测试，确定 L6/L7 的真实覆盖边界；避免“回执齐全”替代“判据正确”。

**第三阶段：增量智能机制。** 在冻结测试集上逐个引入脑图、Profession、贝叶斯和 Behavior，以消融证明净增益。没有效果或收益小于维护开销的模块应保持可选。

**第四阶段：多 Agent 与迁移。** 对可分解任务和顺序任务分别做同预算比较，检查来源相关性、共享状态污染与汇总掩盖失败，再决定拓扑与规模。

建议对外采用可证伪措辞：

> 在指定模型版本、工具目录快照、任务分布与预算下，相对配置 B，本配置在 n 个配对任务上的端到端成功率差为 Δpp（95% CI）；每分配任务费用变化为 X%，每正确完成任务费用变化为 Y%，p95 时延变化为 Z%。结果包含失败和重试；对攻击集报告 ASR、正常效用和置信区间。该结果尚未覆盖列出的漂移、租户或不可逆动作场景。

目前能够成立的结论是：这是一套有合理研究动机的上下文与执行治理设计，若干核心机制已有外部实验支持；尚待本项目实验验证的是这些机制的组合收益、超参数、最小必要模块，以及置信度和安全声明能否在真实运行中成立。
