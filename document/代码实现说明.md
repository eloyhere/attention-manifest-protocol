## 2. semantic-typescript 使用约定

- 状态索引、事件、依赖、去重与候选使用库中的有序/无序 Map 和集合；不自行实现通用容器，不使用原生 `Map`/`Set`。
- 流转换使用 `useFrom`、collector、collectable、排序和去重 API。库的回调式 Generator 与 JavaScript `function*` 不应混用。
- 缺失查询采用库 `Optional`。命令型 `get` 可以在缺失时抛领域错误；查询型 `find` 返回 `Optional`，调用方使用 `map/flatMap/filter/isPresent/get/orElse` 处理。
- 类型守卫复用库中的 `isObject/isString/isNumber` 等。范围、有限非负预算、时间戳、路径和权限是领域约束，需要额外验证。
- 树与依赖图具有不同语义。大纲父子结构复用库中的树/森林；一般依赖和关联边单独管理，并限制访问数量和深度。

## 3. 文件与项目大纲

- 大纲节点统一带 `range` 与 `dirty`：

  ```ts
  interface Range { startLine: number; endLine: number; startByte: number; endByte: number }
  ```

  `startLine` 从 0 开始，`endLine` 不包含；`startByte`/`endByte` 是原文本的 UTF-8 字节偏移，`endByte` 不包含。跨行或含中文、emoji 的节点按真实 UTF-8 字节计算，不能按字符数代替。
- `dirty` 表示该节点描述的文本尚未提交到已存储的文件版本：`bufferVersion` 与 `version` 不一致、`FileSnapshot.dirty === true`，或调用方显式传入 `dirty: true`。大纲对象整体也暴露 `dirty`。
- `file/outline.ts` 用 `SynchronousAbstractSyntaxTree` 保存结构化扫描结果的父子关系，提供子树展开（`expand`）、行定位（`locate`）和按名称查询（`find`）。顶层节点以文件根节点为父。范围使用上述 `Range`，父节点范围会自动扩展到包含所有子节点。
- 大纲是**只读结构化预览**：不编译、不做类型检查、不求值、不展开宏、不执行任何代码；语言识别与节点提取来自本仓库内的轻量结构扫描器，不依赖第三方解析器包。
- `file/language` 是语言注册中心：规范化语言 id、扩展名与 MIME；拒绝重复 ID、扩展名或 MIME 冲突；注销后该 ID 永久退休。`resolve(path, mime?)` 用最终路径段的最长后缀匹配，扩展名与 MIME 冲突时返回空 `Optional`；可配置的 fallback 只接受 `text`/`unsupported` 且不把 `application/octet-stream` 当文本。`find`/`load` 返回 `Optional`，懒加载成功缓存一次、失败可重试；`parse` 只对 `outline`/`text` 执行并校验节点结构、范围、重复 ID、父存在与父子包含。
- 内置 **31** 种语言：Markdown、纯文本、TeX、JavaScript、TypeScript、C、C++、Java、C#、Python、Go、Swift、XML、JSON、MySQL、Oracle SQL、SQL Server、HTML、Vue、CSS、SCSS、Sass（文本结构大纲），以及 Word、Excel、PowerPoint、Access、Publisher、Photoshop、CAD、3ds Max、SolidWorks（二进制/专有格式，经 `documentParser` 提供文档大纲；`support` 为 `document`/`tabular`/`unsupported`）。
- `project/outline.ts` 用 `SynchronousRootedForest` 表示目录/文件/模块树，依赖图独立保存；`upsertBatch` 使用版本守卫并在提交前验证完整候选树。节点同样带 `range`（可选输入，默认空范围）与 `dirty`（与 `stale` 同步：来源、规则或依赖更新后置为 `true`）。
- 文件来源、规则、节点或依赖更新会使相关大纲/投影失效。当前传播策略保守地覆盖祖先、后代和反向依赖，可能使同目录其它节点一并 stale；重新计算可恢复其有效投影。
- 结构扫描器只读取声明形状：注释、字符串、代码围栏、heredoc 等内容会被屏蔽后再匹配，避免把其中的关键字当成声明。它不是完整语法分析器，遇到复杂或非常规写法可能少报或漏报；`find`/`lookup` 缺失即表示未识别，不代表源码无效。

### 二进制文档大纲

`src/file/document` 全部用 Node 内置模块实现，不依赖第三方解析器：

- `ZipArchive`：基于 `node:zlib` 的只读 ZIP，支持 stored/deflate；拒绝加密、zip64、危险路径（`..`/绝对/反斜杠/NUL）、重复名，并强制条目数、单条目、总展开量与压缩比预算。
- `parseXml`：最小 XML 读取器；拒绝 DTD/ENTITY 与未知实体，限制深度与节点数，解析命名空间 local 名、属性与文本。
- `createDocumentOutline(path, bytes, options?)`：按路径解析语言，要求该语言有 `documentParser`；校验并冻结返回的 entries。

已实现的结构大纲（只读，写入交给插件）：

| 格式 | 产出 | 关键 locator |
| --- | --- | --- |
| DOCX / `.doc` | 标题、段落、表格；旧版经 FIB + Clx/PlcPcd piece table 还原文本与段落 | `part + paragraph`（1 基，空段落计数但不产 entry） |
| XLSX / `.xls` | 工作表 + 单元格；旧版经 BIFF8 `BOUNDSHEET`/`SST`（含 CONTINUE）/`LABELSST`/`RK`/`FORMULA` | `part + sheet + cell`，cell 的 `parentId` 指向 sheet |
| PPTX / `.ppt` | 幻灯片与文本；旧版经 MS-PPT 记录树（Slide 容器 + `TextCharsAtom`/`TextBytesAtom`） | `part + slide`（1 基） |
| PSD v1 / PSB v2 | 完整图层树：组嵌套（`lsct`/`lsdk`）、`luni` 名称、bounds、blend、opacity；64 位长度分支 | `part: "psd:layers" + paragraph` |
| DXF | 图层、块、实体类型计数 | `dxf:tables` / `dxf:blocks` / `dxf:entities` |
| DWG R13/R14/R2000 | section 容器（编号、偏移、大小）；实体图未解码 | `dwg:sections + paragraph` |
| 3DS | 命名对象块树 | `part: "3ds:objects" + paragraph` |
| `.max` / SolidWorks | 完整 CFB 容器：目录树、每个流的大小/CLSID、SummaryInformation 属性 | `cfb + paragraph` / `cfb:properties + paragraph` |

明确标注无法解析（抛 `unsupported_format`，不返回空大纲）：

- **DWG R2004+**：各 section 为 LZ77 压缩 + Reed-Solomon 加密，必须导出 DXF 或另存 R2000；
- **DWG R10–R12**：无 R13 section locator 表；
- **`.mdb/.accdb`（Access）**：Jet/ACE 需 mdbtools 级的数据页/系统表解码，未实现；
- **`.pub`（Publisher）**：需 libmspub 级逆向实现，未实现；
- 加密的 Word/BIFF 工作簿（`fEncrypted`/`FILEPASS`）明确报错。

CFB 容器里的**专有语义**不解码：3ds Max 场景图/材质/修改器/动画（`ClassData`/`Scene` 流）、SolidWorks 特征树/配置/配合/尺寸。这些流没有公开规范，只能暴露容器元数据与原始字节，不能声称已解析。

以上均是**结构预览**：不解码像素、网格、公式、宏、外部关系，也不修改原文档。

### 字节挂载与按字节读写

专有格式以字节读写，不经过文本解码：

```ts
const file = workspace.mount("model.psd", { mode: "writable", owner: "agent" });
file.snapshot().binary;          // true（自动检测；也可显式 binary: true/false）
const bytes = file.readBytes();  // 可选 { start, end } 字节区间
file.writeBytes(modified);
file.flush();                    // compareAndSwapBytes：锁 + 哈希复核 + 原子替换
file.documentOutline();          // 直接用字节缓冲区，包含未提交编辑
```

- `MountOptions.binary`：`true` 强制字节、`false` 拒绝二进制、省略时先按文本读取并在 `binary_file` 时回落字节。
- 字节挂载下 `read/write/replace/readLines/outline/diff` 抛 `invalid_target`，避免把二进制当文本改坏。
- `FileStoragePort` 增加可选的 `readBytes` / `compareAndSwapBytes`；内存与真实文件系统适配器都已实现。

### 项目类型与环境

`project.kinds` 注册 7 种项目类型：`go`、`tex`、`text`、`photoshop`、`cad`、`max3d`、`solidworks`。每种都带 `environment`：

```ts
interface ProjectEnvironment {
    variables: Record<string, string>;   // 环境变量默认值，如 GO111MODULE / TEXINPUTS / SW_TEMPLATES
    paths: readonly string[];            // 工作区相对路径：源码、资源、模板、输出
    dependencies: readonly EnvironmentDependency[];  // id / version? / manager? / scope / optional?
}
```

- `ProjectKindRegistry`：校验并规范化，`registerMany` 原子提交，重复 id 拒绝，注销后 id 永久退休，`find` 返回 `Optional`，`list`/`snapshot` 为不可变快照，每次成功变更推进 epoch。
- `detect(files)`：纯函数、不访问文件系统；按 marker 权重求和，score 降序 → priority 降序 → id 升序；`best` 返回 `Optional`。
- `project.environment` 提供 `emptyEnvironment`、`mergeEnvironment`（变量覆盖、paths 去重、依赖按 `id+scope` 合并）与 `validateEnvironment`（变量名 `^[A-Z_][A-Z0-9_]*$`、路径必须规范、依赖 scope 合法）。
- `kinds/bridge.ts` 把类型默认值接到具体项目：`createProjectFromKind(kind, scope)` 用 kind 的 `environment` 初始化 `Project`（`kind` 记为类型 id，`notes` 进入配置引导），`applyProjectKind(project, kind)` 合并 kind 默认值并保留项目覆盖（空串表示显式未设置）。
- `project.serie` 是工具链注册中心（npm/pnpm/node/maven/gradle/make/android/ios），登记 markers、capabilities 与**声明式** steps；库本身不执行任何命令。

### 文件写入与替换模式

目的：让 agent 用「范围」而不是「重新生成整段文本」来改文件，减少错位、越界和误替换。

```ts
const workspace = new Workspace({ tenantId, rootId, storage, outline: createOutlineProvider() });
const file = workspace.mount("notes.md", { mode: "writable", owner: "agent" });
```

`file.write(content, target?)`：

- 省略 target：整文件替换（原有行为）。
- `{ mode: "line", start, end }`：0 基、`end` 不含。替换整行文本，并保留原块的行尾换行。
- `{ mode: "byte", start, end }`：UTF-8 字节偏移、`end` 不含，必须落在码点边界；中文和 emoji 不会被截断。
- `{ mode: "outline", id }`：替换该大纲节点的完整 `range`。需要 mount 时提供 `outline` provider（`createOutlineProvider()`），否则 `outline_unavailable`。标题节点覆盖整节，符号节点通常只覆盖声明本身。

`file.replace(target, replacement, options?)` 支持五种定位方式：

- `{ mode: "string", text }`：字面量匹配，**不解释** `$` 转义。
- `{ mode: "regex", pattern, flags? }`：允许 `i m s u v`，拒绝状态化的 `g`/`y`；替换串支持 `$$`、`$&`、`` $` ``、`$'`、`$1`–`$99`、`$<name>`。
- `{ mode: "line" | "byte" | "outline", ... }`：语义与 `write` 相同。

防误操作约定：

- 默认要求**唯一匹配**：0 个 → `no_match`；多个 → `ambiguous_match`（带命中行号）。要改多处必须显式 `all: true`，要改其中一处必须给 `occurrence`（1 基）；两者同时给 → `invalid_target`。
- `regex` 的空匹配、非法模式、非法 flags 一律 `invalid_target`，不会静默清空文件。
- `locate(target)` 只解析命中区域，不修改缓冲区；`planWrite` / `planReplace` 返回 `{ mode, matches, text, changed, bufferVersion }`，可先预览再决定是否提交。
- `expectedBufferVersion` 与当前缓冲区版本不一致 → `buffer_conflict`，防止把编辑套用到已变化的文本上。
- 只读挂载 → `read_only`；宿主版本已变化 → `stale`；真正的提交仍由 `flush()` 走 CAS 与租约栅栏，冲突时保留 dirty 缓冲区。

```ts
// 先预览：拿到命中区域与结果文本，缓冲区保持不变
const plan = file.planReplace({ mode: "regex", pattern: "const (\\w+) =", all: true }, "let $1 =");
console.log(plan.matches.map(match => match.startLine), plan.changed);

// 确认后再应用（同一 target 与 replacement）
file.replace({ mode: "regex", pattern: "const (\\w+) =", all: true }, "let $1 =");

// outline 目标：先取 id，再替换整节
const section = file.outline().find(entry => entry.name === "Section")!;
file.write("## Section\n\nnew body\n", { mode: "outline", id: section.id });
```

### 真实文件系统适配器

`NodeFileStorage` 实现 `FileStoragePort`，把上面的语义落到磁盘：

```ts
const storage = new NodeFileStorage({ root: "/abs/workspace", maxFileBytes: 8 * 1024 * 1024 });
const workspace = new Workspace({ tenantId, rootId, storage, outline: createOutlineProvider() });
```

- **根目录约束**：构造时固定 `realpath(root)`；每个路径先做工作区相对校验（拒绝绝对路径、`..`、反斜杠、NUL），再对父目录 `realpath` 复核前缀，并拒绝指向符号链接的目标文件。
- **跨进程锁**：`NodeFileLock` 用 `<file>.lock` 的 `O_CREAT|O_EXCL` 记录 owner/fence/token/expiresAt；活锁不会被抢占，只有过期锁可接管，且接管后重新读取被移走的记录，若发现对方刚续期则让对方获胜。`<file>.fence` 保存单调递增的 fencing 计数，跨释放、跨进程都不会复用旧 fence。
- **原子提交**：持锁 → 重新读取并核对 hash → 同目录写临时文件 → `fsync` → `rename` → `fsync(目录)` → 清理。任何失败都不会留下部分写入，临时文件会被删除。
- **错误映射**：`ENOENT→not_found`、`EACCES/EPERM/EROFS→read_only`、`ENOSPC→io_error`；目录 fsync 在 Windows 上不可用时静默跳过。
- **拒绝不安全输入**：超过 `maxFileBytes` → `file_too_large`；二进制或非常规编码 → `binary_file`；混合行尾提交 → `mixed_eol`（需先规范化）。
- `createNodeFileTreeHost(storage, scope)` 用同一个适配器实现 `FileTreeHost`，目录列举/元数据/读取共用一套路径与编码规则，避免两套真相。

### 字符集与行尾保真

`charset.ts` 负责：

- 检测 UTF-8 / UTF-16LE / UTF-16BE（含 BOM，以及无 BOM 时的 NUL 分布推断），识别二进制与 UTF-32 等不支持编码。
- 记录 `eol`（`\n` 或 `\r\n`）、`mixedEol`、`finalNewline`、`bom`。
- **编辑缓冲区始终是 LF**；`encodeText` 在提交时恢复原编码、BOM 和行尾，因此对 CRLF / UTF-16 文件的编辑不会悄悄改变文件格式。
- `FileSnapshot` 暴露 `encoding / eol / bom / size`，供 agent 判断文件形态。

### 可验证读、事务与幂等

- `readLines(startLine, count)` 返回 `{ text, range, startLine, lineCount, totalLines, truncated, eol, baseHash, bufferVersion }`：读到的内容自带锚点，编辑时可直接带回。
- `EditOptions.expectedBaseHash`：提交基线已变化 → `version_conflict`；配合 `expectedBufferVersion`，把「读 → 改 → 提交」绑定到同一版本。
- `apply(edits)` / `planApply(edits)`：多条编辑先在影子缓冲区上全部解析成功，再一次性提交，缓冲区版本只加一；任何一条失败都不会留下半成品。
- `diff()`：返回 base→buffer 的 unified diff（3 行上下文），便于 agent 在 `flush()` 前审阅。
- `flush({ idempotencyKey })`：同一 key 重复提交且缓冲区干净时不会重复写入。

### Agent 交互面（哪些导出、哪些屏蔽）

`src/agent/surface.ts` 是声明式的三层注册表，工具名统一为 `attention_manifest_protocol_<module>.<verb>`：

- **agent（模型可见）**：`session`、`turn`、`intent`、`mission`、`goal`、`plan`、`task`、`action`、`attention`、`project`、`workspace`、`cooperation`、`evidence`、`execution`、`budget`（只有 `remaining`）。
- **host（仅宿主）**：`capability`、`manifest`、`provenance`、`receipt`、`verification`、`retrieval`、`model`、`runtime`。
- **hidden（对模型完全屏蔽）**：`workflow`（单写者状态机）、`policy`、`profession`（权限收紧策略）、`behaviour`（发布/撤销）。

关键约束：

1. **上下文由宿主绑定**：`tenantId`/`principalId`/`sessionId`/`turnId`/`attemptId`/`policyVersion`/`cancellationEpoch`/`owner`/`fence` 不允许作为模型参数出现；`assertModelParameters` 会递归拒绝这些键，`assertBinding` 校验绑定完整性。
2. **隐藏模块不可被请求**：`assertAgentAccessible` 对 host/hidden 直接抛错，`createAgentSurface({ only })` 也不能越过。
3. **每个工具声明 `mutating` 与 `authority`**：分发前由宿主检查策略、预算、lease 与 journal；注册表只是"能不能看见"，不是"能不能做"。
4. **写入边界**：`workspace.write` 是唯一文本写入口（CAS + 期望哈希）；专有格式写入由插件负责，`writeBytes` 只是不透明字节提交。
5. **敏感值只给形状**：`project.environment` 返回变量名/路径/依赖与配置缺口（`describe_environment`），不返回变量值。

`describeSurface()` 可生成给提示词或评审用的工具清单与屏蔽模块列表。

`src/agent/gateway.ts` 是这张注册表的实际分发层：`AgentGateway` 只暴露 surface 里的工具，依次校验 binding、工具存在性与可见性、模型参数（禁止 host 上下文字段）、`mutating` 工具的幂等键、`authorize` 授权钩子，最后调用注册的 handler，并**每次调用写一条 journal**（工具、是否变更、幂等键、成功/错误、耗时）。错误码固定为 `binding_invalid` / `unknown_tool` / `not_exposed` / `invalid_parameters` / `unauthorized` / `mutating_requires_idempotency_key` / `handler_missing` / `handler_failed`，便于宿主映射为拒绝或审计事件。网关不实现策略、预算与 lease——那些仍在宿主侧。

### Proxy 懒加载

`reactive` 导出的 `useProxy` 提供读取钩子和只读投影，`useLazyProxy` 提供按属性加载、缓存、手动失效和来源检查。`null` / `undefined` 值使用缓存信封保存，避免缺失值被重复加载。失败的加载不缓存；递归加载显式报错。每次读取缓存也会重新检查来源有效性。

- `FileOutline.lazyTree(resolver)` / `lazyNode(...)`：文件大纲节点的 `children` 首次访问时才创建直接子代理，不展开后代；resolver 必须查询宿主当前版本。JSON 只输出大纲元数据。
- `ProjectOutline.lazyTree()` / `lazyNode(path)`：项目树以当前项目版本缓存节点身份，访问 `children` 时只生成下一层。项目版本更新使旧代理不可消费，新查询产生新投影。
- `FileTree`：宿主文件树适配器，将目录列举与文件正文加载分开，分别在访问 `children` / `content` 时调用 host port；元数据、目录和正文访问分别授权。它不自行扫描磁盘。

懒加载边界是节点物化、目录展开和正文读取；已提供的大纲解析仍需要明确输入源码，不能声称源码解析本身完全惰性。树代理不是原始状态，修改必须走所属领域的命令端口。

## 4. 执行与验证链

```text
宿主创建 Session / Turn 和业务对象
  → WorkflowStore 进行版本、父级、DAG、取消 epoch 检查
  → 注意力选择与 context 编译
  → 模型端口产生 action/response 提案
  → LCP 发现/检查与宿主绑定
  → Executor 逐子调用进行 Policy、Manifest、预算和执行前 journal 检查
  → Invocation / Observation
  → ReceiptCore / 完整性验证
  → 独立业务契约验证
  → EvidenceLedger 产生声明级证据
  → 宿主将有效验收交回领域服务/WorkflowStore
```

执行协调器不自动为用户承接新的意图，也不根据工具退出状态直接标记 Goal 达成。宿主决定验证器来源、业务合同和验证结果是否仍然有效。

## 5. 运行与验证

使用已安装依赖与 Node >=24：

```sh
npm run check:architecture
npm run test:architecture
npm run scenario
npm run build:lib
npm run demo:architecture
npm run build
```

- `scenario`：真实文件系统上的端到端场景（修 bug、幂等提交、stale 检测、租约互斥、BOM/CRLF、码点边界、二进制文档、损坏格式、归档预算、路径穿越、体积上限、项目环境、Agent 网关授权/隐藏工具/参数注入/审计日志）。它同时在 `test:architecture` 中运行。

- `check:architecture`：严格类型、无未使用符号、可擦除 TypeScript 语法。
- `test:architecture`：自动发现 `src/**/*.test.ts`，使用 Node 测试运行器。
- `build:lib`：输出 JavaScript 和类型声明到 `lib`。
- `demo:architecture`：本地只读绑定→账本→回执→业务验证→Evidence；不调用外部模型或 MCP 服务。
- `build`：编译并打包上下文编译演示页面，不启动任何服务。

`architecture` 在这些脚本名中表示检查范围，不是源码目录。

## 6. 当前边界

当前实现是可测试的宿主无关领域核心和内存适配器。它没有实现生产级多进程一致性、OS 沙箱、真实远端 MCP/OAuth、完整 JSON Schema 执行器、模型供应商 SDK、持久数据库、跨服务事务或分布式恰好一次保证。

- Workspace 的 CAS 和 fencing 在内存适配器内成立；`NodeFileStorage` 用锁文件 + 哈希复核 + 原子替换把同一语义落到本地磁盘，但它是**建议锁**：绕过本库直接写文件的进程仍可能造成竞争，最终以哈希复核失败（`version_conflict`）暴露。跨主机一致性、分布式锁和网络文件系统需要宿主另行保证。
- 适配器只读写已存在的文件，不提供创建目录、重命名、删除等文件系统管理操作；编码支持限于 UTF-8 与 UTF-16LE/BE，UTF-32 与二进制按不可编辑拒绝。
- Workflow 的 snapshot/restore 重建纯状态，不重新执行外部效果；恢复后仍需授权、预算与未知副作用对账。
- Executor 调用的是宿主提供的类型化函数。它不对任意代码进行 `eval`，也不能用进程内调用冒充安全沙箱。执行前 journal 钩子由宿主提供持久化实现。
- 远端 TaskHandle 目前提供分型合同；真实任务轮询、取消、MRTR 与网络断连恢复需要连接器实现。
- 默认 Token 计量使用保守估计；上线应传入对应模型的 tokenizer 和费用/缓存数据。
- Evidence 与 Behavior 的验证和独立样本键由受信宿主提交。签名、验证标记和多个样本不自动证明真实正确性或统计独立。
- 大纲是来源版本绑定的结构化预览，不授予文件读写权限；扫描器只识别声明形状，不能当作编译器、语言服务器或类型检查器。二进制文档（Office/PSD/CAD/3DS/归档）只做只读结构解析，**写入由插件负责**；`writeBytes` 只是不透明字节提交，不理解格式。
- 明确未实现解码：Access `.mdb/.accdb`（需 mdbtools 级）、Publisher `.pub`（需 libmspub 级）、DWG R2004+（section 压缩+加密）、DWG R10–R12、加密的 Word/BIFF 工作簿。它们会抛 `unsupported_format` 并说明原因，而不是返回空大纲。
- CFB 容器内的专有语义（3ds Max 场景图/材质/动画、SolidWorks 特征树/配置/尺寸）没有公开规范，只解析容器目录、流大小/CLSID 与文档属性。

上述边界必须在后续真实适配器、故障注入和端到端环境验收中继续验证。
